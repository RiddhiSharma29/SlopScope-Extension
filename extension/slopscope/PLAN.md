# SlopScope: 10-day plan (Wed 14 Oct → exhibition Sat 24 Oct 2026)

Working name. Rename freely.

## 1. Positioning: how you beat Impeccable

Impeccable (Paul Bakaus, open source) is a DevTools-panel extension that flags UI anti-patterns on a rendered page. Its store listings mention 24 patterns (Chrome) and 41 (Firefox), including some copy tells such as em-dash overuse and buzzwords. Don't claim it lacks text checks; claim you go **wider and further**:

| Area | Impeccable | SlopScope (this repo) |
|---|---|---|
| UI patterns | Yes (core strength) | Yes, 19 rules, own implementation, plus blur-orbs, glassmorphism |
| Text | Some | 8 rules incl. persona names, round-number claims, sentence-length burstiness |
| **Images** | No | AI-host URLs, generator filenames, placeholder/stock hosts, alt text, smooth-gradient pixel check |
| **Source / code** | No | App-builder fingerprints (Lovable, Vite, Next starters), Tailwind purple gradients, dead links, div soup, section-label comments |
| **Score** | Findings list | 0-100 slop score + per-category scores + verdict |
| **Auto-fix** | No | Live fix preview and "Fix all" with before/after score |
| **History** | No | Dashboard: Hall of Slop ranking, compare two scans, rule frequency, CSV/JSON export |
| **Validation** | n/a | Benchmark script + labelled test set → precision/recall numbers (see §5) |

Your one-line pitch: **"Impeccable tells you what looks AI-made. SlopScope scores it across UI, text, images and code, fixes it, and proves it works on a labelled benchmark."**

## 2. Scope tiers

**Tier 1 (MVP, done in this scaffold):** extension, 4 rule packs, overlay, score, popup, dashboard.

**Tier 2 (days 3-6, pick 2-3):**
- Optional LLM judge: user pastes an API key in options; send the page's visible headline/body text (and optionally a downscaled screenshot) for a 0-100 "sounds generated" opinion shown next to the heuristic score. Keep it opt-in and say what is sent.
- Rule config page: toggle rules, adjust severity, save to `chrome.storage`.
- "Explain" button per finding with a before/after example image.
- Share card: render the score as a PNG ("This site scores 82/100 slop") for screenshots and posters.
- Monotonous-spacing and colour-count rules (Impeccable has similar ones).

**Tier 3 (stretch only if ahead):** Firefox build, CI mode using Playwright (see `tools/benchmark.mjs`), scan whole sitemap.

## 4. Demo script (3 minutes)

1. (20s) Hook: open a landing page generated by a chat tool. "Spot the AI? Most people can't say why."
2. (40s) Click SlopScope. Overlay lights up, score 78, "Peak slop". Hover a gradient heading and a feature grid.
3. (40s) Show the four categories. Point to an image finding and a generator fingerprint in the source.
4. (30s) Click **Fix all**. Score drops to ~40. "Fixes are live previews, not rewrites of your code."
5. (30s) Open dashboard → Hall of Slop with 8 pre-scanned sites. Compare before/after.
6. (20s) Benchmark slide: "On 50 labelled sites: precision X, recall Y." End on "SlopScope passes its own scan."

Pre-scan 8 sites the night before so the dashboard is populated even if Wi-Fi fails. Keep two local HTML demo pages (one sloppy, one clean) in `demo/` as offline fallback.

## 5. Evaluation (what makes it a project, not a toy)

- Build a labelled set: ~25 AI-generated, ~25 human-designed pages. Be explicit about how you labelled (source of page, builder badge, your own generation prompts). "AI-made" ground truth is fuzzy, so say so.
- Metrics: precision, recall, F1 at a score threshold (try 40), plus per-rule hit rate on each class.
- Ablation chart: accuracy with only UI rules vs UI+text vs all four. This directly shows your added scope matters.
- Report limitations honestly (below). Examiners reward that.

## 6. Limitations to state up front

- Heuristics detect *patterns associated with* generated sites, not authorship. A human can use a purple gradient; an AI-built site can look original. Call the output a **slop score**, never "AI probability".
- Image checks are URL, filename and simple pixel statistics. They cannot reliably detect a generated photo. An optional vision-model check is the honest upgrade.
- Cross-origin stylesheets and images can't always be inspected from a content script.
- Fixes are live DOM previews, not source patches.

## 7. Likely viva questions

- *How is this different from Impeccable?* See §1 table.
- *How do you know the rules work?* Benchmark + ablation (§5).
- *What about false positives?* Severity weights, caps on repeated hits, and the fact that scores are relative. Show the noisiest rule you removed and why.
- *Why not just use an LLM?* Heuristics are fast, offline, private and explainable; the LLM judge is an optional second opinion.
- *Privacy?* Everything runs locally; history stays in `chrome.storage.local`; LLM mode is opt-in.
- *Scoring formula?* Per rule: `min(18·sev, 6·sev·(1+log2 n))`; per category sum capped at 100; overall = ½ weighted average (UI .30, text .25, image .20, code .25) + ½ worst category.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Rules fire on everything | Benchmark early (Day 4), prune |
| Demo site changes or Wi-Fi dies | Pre-scanned history + local demo pages + video |
| Scope creep | Freeze on Day 8 |
| Can't explain a rule | Every rule has a `why` string; learn them |
